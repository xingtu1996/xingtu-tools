把元宝变成 AI 前沿内容捕手

分享链接解析 + 本地归档工作流专题 · 行途 / XingTu · 2026-08-25

一句话结论：微信里转发给元宝做摘要的链接，本质是一个 yb.tencent.com/wx/ct/... 分享页； 它只做了 User-Agent 检测，伪装成微信移动端请求即可拿到完整正文。配合一个零依赖的开源解析脚本， 就能把散落在聊天里的 AI 前沿内容批量抓回本地、结构化入库、二次创作——形成内容复利。

一、为什么这件事值得做（行途视角）

AI 进化快，早期实践极易贬值。响应力是行途立 IP 的核心：谁先把一手前沿实践转成可发布内容，谁就抢到占位。 但你平时刷到的好东西——视频号一条 OpenHands 的安利、公众号一篇 Agent 架构拆解——往往只是顺手「转发给元宝要个摘要」， 然后就沉在聊天记录里，再也没翻出来。

痛点很清楚：内容在微信内、在元宝会话里，不在你的内容库里。要做成可发布的 AI 专题，先得把它「捞」出来。

二、核心技术发现（已实测）

元宝分享页是 Next.js SSR 渲染，全部正文已内嵌在页面的 __NEXT_DATA__ JSON 里， 层层字符串化嵌套，无需登录、无需逆向 API。普通浏览器打开会提示「请在微信客户端打开」， 根因只是服务端校验了 User-Agent。

# 伪装成 iPhone 微信，直抓即可拿到全文
curl -A "Mozilla/5.0 (iPhone; ... ) Mobile/15E148 MicroMessenger/8.0.38 ... \
  NetType/WIFI Language/zh_CN" -e "https://wx.qq.com/" "https://yb.tencent.com/wx/ct/f/XXXX"

正文结构位于 props.pageProps.data.conversation_info.data → 解码后取 extra（字符串化消息数组）或 dataObj.mergedQuestion，每条消息的 speechesV2[].content[] 承载正文与富媒体（视频号消息含 author / content / coverUrl 等）。

四、开源工具：yuanbao_share_parser.py

工作区已有更完整的「元宝对话挖掘」管线（yuanbao_fetch.py + 编排器），但那套绑定了系统 curl、 靠「听全文」锚点做 HTML→Markdown 启发式。本工具换了个更干净、更适合开源的思路：

维度yuanbao_fetch.py（既有）yuanbao_share_parser.py（本工具）
抓取方式调系统 curl 伪装微信 UA纯 urllib，零外部依赖
解析思路可见文本 → 启发式（依赖锚点）直接解析 __NEXT_DATA__ 结构化 JSON
输出单篇 Markdown + manifest 去重Markdown / JSON，含 speaker 角色与富媒体
定位内容库落盘主力轻量、可移植、易开源 / 嵌入
# 用法
python3 yuanbao_share_parser.py "https://yb.tencent.com/wx/ct/f/YFuacU3Vg4MNk3"
python3 yuanbao_share_parser.py "<URL>" --format json --output out.json
python3 yuanbao_share_parser.py "<URL>" --list   # 只看消息角色概览

实测输出（示例链接）：解析出 1 条 human 消息 + 富媒体元数据（来源账号 AI慢聊、封面图、时长 7s、来源「微信视频号」）， 并附带对话元信息（agentId=yuanfang、conversationId、platform=WEB）。

合规红线

只用于你自己转发 / 收藏的链接的本地归档与学习。工作区既有 export_yuanbao.py 带「去敏闸门」：闪记若含明文客户名 / 人名 / 地点 / 敏感信息，直接转发 = 泄露给第三方，踩穿合规红线。 开源工具同样遵守——转发前先过去敏，绝不碰敏感 / 客户 / 个人数据。
